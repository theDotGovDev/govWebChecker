# Implementation Plan: analysis and presentation

**Branch**: `002-analysis-presentation` | **Date**: 2026-08-24 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/002-analysis-presentation/spec.md`

## Summary

Turn a live record into answers a reader can trust, and publish them. The record
holds 10,748 observations across two tiers; nothing currently turns them into a
statement anyone can act on.

The technical approach is almost entirely about **what the build refuses to
produce**. A figure is not a number — it is a number plus its tier, population,
window, sample count and vantage, and a build that cannot attach those fails
rather than shipping a bare number (FR-251). Every other design decision follows
from making that cheap to obey and impossible to bypass.

Three decisions are settled and are planned to, not reopened: per-dimension
standings with no composite (D1), a listing for every site (D2), and the site —
not the registered domain — as the listing unit (D3).

## Technical Context

**Language/Version**: TypeScript on Node 22, `"type": "module"`, `tsc` to `dist/`

**Primary Dependencies**: none, and none added. The site is plain static HTML
generated by `src/site`; introducing a generator or template engine would be a
dependency for something a few hundred lines already do.

**Storage**: the existing append-only JSONL record under `data/`. Read-only here.

**Testing**: `node --test`, as everywhere else. Presentation is tested by
asserting over the model and the rendered string, never by a browser.

**Target Platform**: static files in `docs/`, deployed by `pages.yml`

**Project Type**: single project, extending `src/site`

**Performance Goals**: the build reads the whole record and writes the whole
site in one pass, well inside a CI step. At today's 10,748 rows this is
milliseconds; the relevant number is growth — see Constraints.

**Constraints**:
- **No traffic.** The build reads `data/` and nothing else. No fetch, no DNS.
- **Growth.** The record grows by ~1,400 hot rows/day and ~2,300 census rows/day,
  so roughly 1.4M rows/year. A build that holds every row in memory to render one
  page will not age well, and D2 means ~16,535 listings per build.
- **Absence.** ~1 listing in 7 will have nothing but our own failure to report.

**Scale/Scope**: 58 hot-tier hosts, 16,535 census domains, 2 tiers, 1 dimension
(availability), ~16,600 generated pages.

## Constitution Check

*GATE: passed before Phase 0; re-checked after Phase 1 below.*

| Principle | Gate | Status |
| --- | --- | --- |
| I — Measurement, not load | Does this feature generate traffic to any target? | **PASS** — it reads the record. FR-250 makes it structural, and the build has no network path at all, which is stronger than a rule |
| II — Only the public surface | Does it need a credential, or touch personal data? | **PASS** — no credentials. FR-244 additionally refuses to republish the security-contact emails the registry carries |
| III — Politeness is structural | Are the limits affected? | **N/A** — this feature sends nothing |
| IV — An observation is a fact | Does it edit history or discard failures? | **PASS** — read-only. FR-242 keeps corrections as superseding observations |
| V — A published number carries its method (NON-NEGOTIABLE) | Can any figure be published without its method? | **PASS by construction** — see *The Figure type* below. This is the gate the whole design exists to satisfy |

**Development-workflow gates**: spec written and decided; test-first; no traffic
in tests; `ARCHITECTURE.md` updated in the same change; PR merges only on green.

### How Principle V is met by construction rather than by discipline

A rule that says "always state the method" is obeyed until someone is in a hurry.
So the plan makes the unmethodded case unrepresentable:

- There is **no `number` in the view model**. The only way to express a published
  quantity is a `Figure`, which cannot be constructed without tier, population,
  window, sample count and vantage.
- The renderer accepts `Figure`, never `number`. A developer wanting to print a
  bare number has to add a new code path, not forget an argument.
- A test asserts that every numeric-looking token in the rendered HTML traces to a
  `Figure` — so the guarantee is checked against the *output*, the way `verify`
  checks the record rather than the code.

This is the same move the project already made twice: politeness lives inside the
checker, and coverage is proved from the record. The pattern is "make the wrong
thing hard to express", and it is why FR-251 is a build failure rather than a
style note.

**Structure Decision**: extends the existing single project. `src/site` grows
from two files to seven because the current two do one page; this feature does
three page *kinds* and ~16,600 pages. The split is by responsibility — deriving
figures, ordering them, shaping series, and writing files — not by page.

## Phase 0 — Research

See [research.md](./research.md). Seven questions, all resolved:

| | Question | Decision |
| --- | --- | --- |
| R1 | How is Principle V enforced rather than promised? | A `Figure` type the renderer requires, plus an output-level test |
| R2 | 16,535 listings in one build — feasible? | Yes, streaming by target; measured, not assumed |
| R3 | How is a weekly cadence drawn without implying the days between? | Discrete marks; the series type forbids interpolation |
| R4 | What does a listing with nothing but our failure say? | Leads with the unknown; a stated template, tested |
| R5 | How do the tiers stay apart in one page? | Tier is a parameter of every view; no function takes both |
| R6 | Does the record grow past a whole-file read? | Not for years; monthly partitioning already bounds it |
| R7 | Three hosts carry two `target_id`s each — found in the live record | The listing is keyed on **host**, not `target_id`; a `target_id` key would split `www.irs.gov` across two pages, each stating half its sample count |

## Constitution Re-check (post-design)

Unchanged: **PASS** on all five. The design adds no network path, no credential,
no mutation of the record, and no way to express a figure without its method.

One thing worth flagging that the design *cannot* enforce: FR-243 says the site
must not present a single observation as a characterisation of an institution.
That is a judgement about wording and layout, not a type. It is covered by a
listing template that states the sample count next to every reading, and by
review — but a test cannot prove restraint, and the plan does not pretend
otherwise.
